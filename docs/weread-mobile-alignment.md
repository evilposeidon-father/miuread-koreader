# Kindle 微信读书 · 产品计划（v2）

> **定位（重写）**：我们做的不是"觅阅（MiuRead）这个 KOReader 插件"，而是 **Kindle 上的微信读书客户端**。
> 微信读书手机端 App 就是产品基准与规格书；现有 miuread.koplugin 代码只是实现底座，凡与手机端体验冲突的既有 UI、文案、命名一律按手机端重塑。
> 设计底线不变：**最好的设计是原生设计**——优先 KOReader 原生组件与事件；自绘只保留 KOReader 原生做不到的少数常驻元素（书架封面墙、底部 Tab、阅读页顶部/底部常驻栏、hero 卡片）。
> 面板/菜单类交互逐个映射到 KOReader 具体事件（目录/字体/进度/书签各走各的入口），不用通用菜单路由（4.5.42→4.5.43 教训）。

---

## 1. 对齐策略

| 标记 | 含义 | 处理 |
| --- | --- | --- |
| ✅ | 已具备且体验达标 | 保留，纳入回归 |
| 🔧 | 可以做到 | 实现（以手机端为规格） |
| ⚠️ | 手机端能力在 Kindle/e-ink 上做不到 | 靠齐：布局/命名/层级/空态对齐，实现降级为原生组件 |
| ❌ | 依赖腾讯服务/会员/社区/无 API，不该做 | 明确不做，不占位 |

## 2. 基准：微信读书手机端（对齐目标，听书已排除）

- **底部四 Tab**：书架 / 书城 / 发现 / 我的（Kindle 版：三 Tab，见 D1）。
- **书架**：顶部搜索 + 排序/编辑；「继续阅读」大卡（进度+最近阅读）；书籍网格（封面+标题+进度角标）；书单；公众号入口。
- **书城**：搜索、分类、榜单/推荐位。
- **我的**：阅读时长（今日/本周）、我的想法/划线、书架管理、设置。
- **阅读页**：顶部（返回 ← + 书名 + 当前章节）；底部工具栏（目录/进度/字体 Aa/亮度/更多 ···）；长按选词菜单（划线样式/笔记/复制/查词）；点击划线 → 想法弹层（想法/样式/颜色/删除）；章内/章末想法；进度滑杆；书签；主题（护眼米色默认/纯白/夜间）+ 亮度。
- **设计语言**：浅灰页面底 + 白色卡片、绿色点缀；阅读页米色护眼底 + 深灰文字；线性图标、动效克制。

## 3. 已定决策（v2 生效，替代 v1 §6 待确认）

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | **底部三 Tab：书架 / 书城 / 我的**（原生 TabBar 样式） | 手机端四 Tab 中"发现"为社区流（❌），其余三 Tab 一一对应；比顶部分区更贴近手机端 |
| D2 | **书城 = 搜索微信读书（核心）+ 公众号 + 线上分类（待验证 API）**；已下载/本地书籍/本机分类移回**书架页内分组** | 无商城/榜单 API（已核查代码库端点）；R1 评审修正：不把本地内容伪装成书城 |
| D3 | **阅读主题**：夜间=KOReader 原生 night_mode（已实现）；护眼米=面板皮肤靠齐（cre 正文底色不可改）；纯白=KOReader 默认 | R4 核对：手机端纸色在 KOReader cre 上无用户级背景色设置，正文底色靠齐，面板皮肤用米色 |
| D4 | **听书（TTS）/ AI 听书 ❌ 不做** | 用户已确认；不占位 |
| D5 | **文案对齐仅限功能词**：书架/书城/我的/想法/划线/继续阅读/阅读时长等用手机端措辞；「微信书架」→「书架」 | 微信读书是**对齐目标**，不是界面品牌：**首页标题保持「觅阅」不改**（用户确认），不冒充官方客户端；「关于/设置」保留非官方声明 |

### 4.5 我的页

| 手机端 | 现状 | 策略 |
| --- | --- | --- |
| 阅读时长（今日/本周） | 阅读周报藏在工具与维护 | 🔧 「我的」首页时长卡（今日+本周） |
| 我的想法/我的划线 | 批注搜索 | 🔧 两个原生列表入口 |
| 书架管理 | 首页分区 | 🔧 归入「我的」 |
| 设置 | 「觅阅设置」 | 🔧 改名「设置」并归入「我的」（D5） |

### 4.6 明确不做（❌）

- 发现页社区想法流、好友关系、互动
- 书城榜单/推荐位/商城（无 API）
- 听书 / AI 听书（D4）
- 无限卡/会员/组队/支付
- 动画动效、彩色 UI（墨水屏约束）
- 手机端原生手势（滑动返回、双指缩放）——用 KOReader 手势体系

## 5. 分期计划

### P0 — 设计基线（已开工）

- 产出：设计令牌（WeRead 手机端色板 → 墨水屏灰阶映射、字号层级、间距、卡片/网格规格）+ 原生组件映射表（每个手机端元素 → KOReader 原生组件/事件，含自绘保留清单）。
- 文件：docs/weread-design-tokens.md
- **验收**：映射表无未标注项；令牌文件评审通过。

### P1 — 信息架构与品牌

- 底部三 Tab（书架/书城/我的）；书架=落地；书城=搜索+公众号+线上分类（待验证）；我的=时长+想法+划线+设置。
- 文案统一（D5）；动作条瘦身；控制中心保留。
- **验收**：首页 ≤2 次点击到达任一功能；layout_version 迁移无回归（Lua 套件 + 结构守卫）。

### P2 — 阅读页核心（R1 评审调整：提前，日频核心且风险最高）

- 快捷面板五组前置（更多/目录/进度 + 字体/亮度行）+「更多」入口；进度滑杆点按即跳转（松手生效已满足）。
- 真机项（P5）：常驻顶部/底部栏、点正文呼出/收起——e-ink 点击拦截风险最高，先真机验证再实施。
- **验收**：真机逐项核对 §4.4；每个面板直达且可改（4.5.43 复检）。

### P3 — 书架页（原 P2 顺延）

- ✅ 继续阅读 hero：进度条 + 「继续阅读」标题 + 来源标签；✅ 书架排序（最近阅读/最近加入/书名/作者，纯函数 HomeLayouts.sort_rows，入口：首页与书架→书架排序）；✅ 空态：空书架→「书架空空，去书城逛逛吧」+ 一键去书城；✅ 页内分组=既有来源 Tab（书架/已下载/本地书籍/公众号）。
- 待办：编辑模式多选（B11）、公众号/书单入口卡、本机分类入口。
- **验收**：信息密度/入口顺序与手机端一致；本地聚合在书架页内而非书城。

### P4 — 阅读页收尾 + 我的与统计

- 长按选词核对完成（划线=自动下划线主路径；笔记=点击划线弹层；复制/查词 B12）；夜间=原生 night_mode（✅）；护眼米/纯白=靠齐（B5）；时长卡（本机统计 A16 + 「阅读周报 ›」入口，云端同源 B13）；设置归入。
- 后续（P5+）：我的想法/划线「最近列表优先，搜索次级」。
- **验收**：时长与手机端同源可对；夜间/目录/字体验证结论记录。

### P5 — 打磨与真机验证

- 手势冲突、翻页刷新、性能、回归（Lua 213 + 结构守卫 23）；Kindle PaperWhite 3 全流程走查后发版。

## 6. 风险与坑

- **4.5.42/43 教训**：面板委托必须映射具体 KOReader 事件，先真机验证再默认启用。
- **e-ink 约束**：无彩色/动效/慢刷新——一切对齐以灰阶原生表达为准，不追求像素级一致。
- **无 API 模块**（榜单/社区/会员）一律 ❌ 或 ⚠️ 靠齐，禁止伪造。
- **非官方身份**：UI 贴近手机端但保留非官方声明（D5 备注）。
- **会话互顶**：手机端活跃可能顶掉 Kindle 会话（keepalive 已缓解）；「我的」页显示账号状态。
- **版本节奏**：每 Phase 独立发版，不攒大爆炸。
